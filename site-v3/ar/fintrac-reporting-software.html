برنامج الإبلاغ إلى FINTRAC وتقديم التقارير عبر API

تقاريرك إلى FINTRAC تُفحص وتُعتمد وتُتابع في مكان واحد.

تمرّر منصة الإبلاغ لدينا بيانات معاملاتك عبر فحوص قاعدة الـ 24 ساعة والتحقق من الصحة والاعتماد، ثم تقدّمها عبر خدمة تقديم التقارير بواجهة API لدى FINTRAC (FINTRAC API report submission) إذا كنت مسجَّلاً فيها، وتحتفظ بالسجل.

احجز استشارة تابع القراءة عرض سعر · بعد مكالمة تحديد النطاق

معظم العمل في الإبلاغ إلى FINTRAC يجري قبل أن تضغط زر الإرسال.

تتوزع المعاملات على أكثر من نظام. وقد يتعين جمع المعاملات الأصغر بموجب قاعدة الـ 24 ساعة. وتضيع بيانات الشخص الذي يُجري المعاملة والمستفيد، ويحتاج كل تقرير إلى فحص قبل إرساله، ويجب تصحيح التقرير المرفوض وإعادة تقديمه. والجداول والبريد الإلكتروني تجعل كل ذلك بطيئاً ويصعب إثباته.

تغطي منصتنا التقارير الخمسة التي تُقدَّم إلكترونياً: تقارير المعاملات المشبوهة، وتقارير المعاملات النقدية الكبيرة، وتقارير التحويلات الإلكترونية للأموال، وتقارير معاملات العملة الافتراضية الكبيرة، وتقارير مدفوعات الكازينو. ويبقى فريق الامتثال لديك هو من يقرر ما يُبلَّغ عنه. وتتولى المنصة الفحص والتوجيه وحفظ السجلات المحيطة بهذا القرار. ويُؤكَّد السعر بعد مكالمة تحديد النطاق.

كيف تصل التقارير إلى FINTRAC

يجب على أي نشاط تجاري لديه اتصال بالإنترنت أن يرسل إلى FINTRAC إلكترونياً تقارير المعاملات المشبوهة، وتقارير المعاملات النقدية الكبيرة، وتقارير معاملات العملة الافتراضية الكبيرة، وتقارير التحويلات الإلكترونية للأموال، وتقارير مدفوعات الكازينو. أما تقارير ممتلكات الأشخاص أو الكيانات المدرجة فلا تزال تُقدَّم على نموذج ورقي. وتذكر صفحة طرق الإبلاغ لدى FINTRAC نظامين إلكترونيين للإبلاغ، إضافة إلى إجراء مشترك لإرسال تقارير EFTR إلى FINTRAC ووكالة الإيرادات الكندية (Canada Revenue Agency) في الوقت نفسه:

  • نظام الإبلاغ عبر الويب لدى FINTRAC (FINTRAC Web Reporting System). تُدخل التقارير وتقدّمها واحداً تلو الآخر في المتصفح. وتقول FINTRAC إنه موجّه للأنشطة التجارية ذات أحجام الإبلاغ المنخفضة.
  • تقديم التقارير بواجهة API لدى FINTRAC (FINTRAC API report submission). اتصال مباشر بين الأنظمة يرسل بيانات التقارير إلى FINTRAC مباشرة، وهو موجّه للأنشطة التجارية ذات الأحجام الأعلى.

يجري إيقاف أنظمة الدفعات القديمة. وقد انتهت الفترات الانتقالية التي حددتها FINTRAC لنقل الإبلاغ ذي الأحجام الأعلى إلى واجهة API في 6 نوفمبر 2023 لتقارير LCTR وLVCTR، و3 يوليو 2024 لتقارير STR، و22 أغسطس 2024 لتقارير EFTR وتقارير مدفوعات الكازينو (FINTRAC، تقديم التقارير بواجهة API، تم التحقق في 15 نوفمبر 2026).

ثلاث طرق لتقديم التقارير إلى FINTRAC

بالنسبة إلى التقارير الإلكترونية الخمسة، يكون الخيار بين استخدام أحد نظامَي FINTRAC مباشرةً، واستخدام منصة إبلاغ تُعدّ التقارير وتقدّمها عبر أحدهما. ويجب على الشركة التي لا تملك القدرة التقنية على الإبلاغ إلكترونياً أن تستخدم النماذج الورقية لدى FINTRAC (FINTRAC، طرق الإبلاغ).

الخيارآلية العملموجّه إلىما تُعدّهالفحوص قبل التقديم
نظام الإبلاغ عبر الويب لدى FINTRAC (FINTRAC Web Reporting System)تملأ كل تقرير وتقدّمه في المتصفح.أحجام الإبلاغ المنخفضة، وفقاً لـ FINTRACالوصول إلى النظام، عبر مراسلة FINTRAC أولاً على F2R@fintrac-canafe.gc.ca، ومستخدمون بأدوار محددة: مسؤولو إدخال البيانات يمكنهم إنشاء التقارير فقط، ومسؤولو التحقق والتقديم يقدّمونها.التحقق من الصحة لدى FINTRAC: رسالة رفض عند نقص معلومات إلزامية، وتحذير عند نقص معلومات مصنّفة بأنها «إلزامية إن انطبقت».
اتصالك الخاص بواجهة API لدى FINTRACترسل أنظمتك بيانات التقارير مباشرةً إلى FINTRAC.أحجام الإبلاغ المرتفعة، وفقاً لـ FINTRACتطبيق ومفاتيح سرية عبر بوابة API لدى FINTRAC، وتطوير خاص بك وفق مخططات JSON وقواعد التحقق من الصحة لدى FINTRAC، مع تحديثه كلما حدّثتها FINTRAC.أي فحوص تبنيها بنفسك، ثم رسائل التحقق من الصحة لدى FINTRAC.
منصة إبلاغ، مثل منصتناتُستورد بيانات المعاملات وتُفحص وتُعتمد، ثم تُقدَّم عبر خدمة تقديم التقارير بواجهة API لدى FINTRAC (FINTRAC API report submission) إذا كنت مسجَّلاً فيها.تقدّم عبر واجهة API لدى FINTRAC، أو تُعدّ بيانات التقارير لقناتك الحالية لدى FINTRAC إلى أن تُسجَّل في الخدمةأنواع التقارير والحدود وقواعد التجميع ومطابقة الحقول ومسارات الاعتماد، يضبطها مختص في الامتثال. ويظل التسجيل في خدمة API مطلوباً.فحوص قاعدة الـ 24 ساعة، والتحقق من الصحة قبل التقديم مع عرض التحذيرات بمعزل عن الأخطاء المانعة، والاعتماد وفق مبدأ العيون الأربع (maker-checker).

أيّاً كان ما تستخدمه، تظل شركتك مسؤولة عن تقاريرها. ويشرح دليل نظام الإبلاغ عبر الويب وصفحة تقديم التقارير عبر API لدى FINTRAC كل نظام.

ما الذي ينطوي عليه تقديم التقارير بواجهة API لدى FINTRAC (FINTRAC API report submission)

لاستخدام واجهة API تحتاج إلى تطبيق ومفاتيح سرية، يُعدّها المسؤول التقني لديك عبر بوابة API لدى FINTRAC. والنشاط التجاري الذي يقدّم أحجاماً أكبر ولا يملك بعد صلاحية الوصول إلى API يتواصل مع FINTRAC على F2R@fintrac-canafe.gc.ca.

تقدّم FINTRAC مجموعتين من نقاط النهاية (endpoints)، إحداهما للتقارير الفردية والأخرى للتقديم المجمّع، وتتيح كل منهما إنشاء تقرير مقدَّم أو تعديله أو حذفه. ويمكن أن يضم التقرير الفردي ما يصل إلى 500 معاملة (25 ميغابايت). ويمكن أن يضم الملف المجمّع ما يصل إلى 5,000 تقرير وما يصل إلى 5,000 معاملة لكل تقرير، ضمن 300 ميغابايت. وتنشر FINTRAC مخططات JSON وقواعد التحقق من الصحة لكل نوع من التقارير.

تُنشئ منصتنا بيانات التقارير بالصيغة التي تتوقعها واجهة API لدى FINTRAC، وتقدّم التقارير المعتمدة فرادى أو مجمّعة، وتسجّل رد FINTRAC على كل تقرير. وإذا لم يكن نشاطك التجاري مسجَّلاً بعد في خدمة API، فإننا نساعدك في التسجيل. وحتى ذلك الحين، تُعدّ المنصة بيانات تقارير متحققاً من صحتها ومعتمدة لتقديمها عبر قناتك الحالية لدى FINTRAC، وتسجّل الحالة مقابل التقرير.

التقارير التي تغطيها المنصة

هذه هي الحدود والمواعيد النهائية الواردة في إرشادات FINTRAC، كما نلخّصها في دليلنا للإبلاغ إلى FINTRAC. وتعتمد التقارير التي يجب عليك تقديمها على نشاطك التجاري وأنشطتك.

التقريرمتى ينطبقالموعد النهائي
تقرير المعاملات المشبوهة (STR)وجود أسباب معقولة للاشتباه في أن معاملة ما مرتبطة بغسل الأموال أو تمويل الإرهاب أو التهرب من العقوبات. لا يوجد حد أدنى للمبلغ.في أقرب وقت ممكن عملياً
تقرير المعاملات النقدية الكبيرة (LCTR)تتلقى نقداً بقيمة 10,000 دولار أو أكثر، في معاملة واحدة أو في معاملتين أو أكثر تُلزمك قاعدة الـ 24 ساعة بجمعها.15 يوماً تقويمياً
تقرير التحويلات الإلكترونية للأموال (EFTR)تبدأ تحويلاً إلكترونياً دولياً للأموال أو تكون المتلقي النهائي له بقيمة 10,000 دولار أو أكثر، في تحويل واحد أو في تحويلين أو أكثر تُلزمك قاعدة الـ 24 ساعة بجمعها.5 أيام عمل
تقرير معاملات العملة الافتراضية الكبيرة (LVCTR)تتلقى عملة افتراضية قيمتها 10,000 دولار أو أكثر، في معاملة واحدة أو في معاملتين أو أكثر تُلزمك قاعدة الـ 24 ساعة بجمعها.5 أيام عمل

تُقدَّم تقارير ممتلكات الأشخاص أو الكيانات المدرجة ورقياً، لذا لا تتعامل معها المنصة. أما تقارير مدفوعات الكازينو، التي تنطبق على الكازينوهات، فلها مسار عمل خاص بها.

فحوص قاعدة الـ 24 ساعة

بالنسبة للمعاملات النقدية الكبيرة ومعاملات العملة الافتراضية الكبيرة، تعني قاعدة الـ 24 ساعة لدى FINTRAC أن معاملتين أو أكثر بأي مبلغ يبلغ مجموعها 10,000 دولار أو أكثر خلال 24 ساعة يُبلَّغ عنها معاً، عندما تعلم أنها أُجريت من الشخص أو الكيان نفسه أو نيابةً عنه، أو أنها لصالح المستفيد نفسه. أما التحويلات الإلكترونية للأموال ومدفوعات الكازينو فلها قواعد تجميع خاصة بها. وتتوقع FINTRAC تطبيق القاعدة في جميع مواقعك، وهو أمر يصعب تنفيذه يدوياً عبر الفروع والوكلاء وقنوات الدفع.

لا تعمل القاعدة بالطريقة نفسها في كل تقرير. فالمعاملات التي تُجمع تعتمد على نوع التقرير والتوقيت ومن أجرى المعاملات والأطراف الخارجية والمستفيدين. وتطبّق المنصة فحوصاً قابلة للتهيئة لكل نوع من التقارير، وتعرض المعاملات التي جمّعتها. ويؤكد فريقك ما إذا كان التقرير مطلوباً.

التحقق من الصحة قبل تقديم التقرير

يعرض نظام الإبلاغ عبر الويب لدى FINTRAC (FINTRAC Web Reporting System) نوعين من رسائل التحقق من الصحة، وفقاً لدليله. فرسالة «مرفوض» تعني أن معلومات إلزامية ناقصة، ولا يمكن تقديم التقرير حتى تُضاف. أما التحذير فيعني أن معلومات موسومة بأنها «إلزامية إن انطبقت» ناقصة أو غير مكتملة. ولا يمنع التحذير التقديم، لكن إذا كانت المعلومات موجودة في سجلاتك فأنت ملزم بإدراجها.

تُجري المنصة فحوصها قبل أن يصل التقرير إلى مرحلة الاعتماد. وهي تفحص:

  • الحقول الإلزامية والحقول «الإلزامية إن انطبقت»؛
  • الصيغ والرموز والحقول المشروطة؛
  • المعلومات الناقصة عن الشخص الذي يُجري المعاملة أو عن المستفيد، وحقول الأطراف الخارجية في تقارير مدفوعات الكازينو؛
  • الأرقام المرجعية المكررة للتقارير والروابط الناقصة بين المعاملات؛
  • التواريخ والمبالغ غير المتطابقة.

تُعرض الأخطاء المانعة منفصلة عن التحذيرات، ليعالج فريقك أولاً ما قد يمنع التقديم. ولا يضمن التحقق من الصحة أن تقبل FINTRAC التقرير.

المراجعة والاعتماد

المراجعة وفق مبدأ العيون الأربع (maker-checker) قابلة للتهيئة. يُعدّ المُعِدّ التقرير ويتحقق من صحته، ويعتمده المراجِع. ويمكن للمراجعين التعليق على التقرير نفسه وإعادته للتصحيح، ويُوثَّق كل إجراء بالوقت، لذا يمكنك أن تُثبت من أعدّ كل تقرير وراجعه واعتمده وقدّمه، ومتى. وتنبّه التذكيرات إلى التقارير التي يقترب موعدها النهائي.

تتطلب تقارير المعاملات المشبوهة تقديراً لا يستطيع البرنامج توفيره. توفر المنصة حقولاً منظّمة للسرد وتوجّه التقرير للاعتماد، لكن تحديد وجود أسباب معقولة للاشتباه وكتابة السرد وقرار التقديم تبقى من مسؤولية مسؤول الامتثال لديك. واستخدام المنصة لا ينقل مسؤوليتك القانونية عن الإبلاغ.

بعد التقديم

قد يعود التقرير المقدَّم مع تحذيرات أو يُرفض. تسجّل المنصة إشعار الاستلام ورقم التأكيد من FINTRAC، وتحتفظ ببيانات JSON التي أُرسلت، وتُسند التصحيحات إلى أحد أعضاء الفريق، وتربط كل نسخة مصحّحة بالأصلية، بحيث يُقرأ تاريخ التقرير كسجل واحد. ويمكنك تعديل التقارير المقدَّمة أو حذفها عبر مسار العمل نفسه.

تُحفظ التقارير المقدَّمة في أرشيف يمكنك تنزيله بصيغة PDF أو CSV. وتُؤكَّد ضوابط مدة الاحتفاظ كتابياً أثناء تحديد النطاق. ويمنح ذلك القائم بمراجعة الفعالية لديك، ومفتشي FINTRAC، سجلاً موثَّقاً بالوقت لمراجعة كل تقرير واعتماده، وبيانات JSON المرسلة، ورد FINTRAC.

ما الذي تبحث عنه في برنامج الإبلاغ إلى FINTRAC

أيّاً كان المنتج الذي تدرسه، فهذه هي الأسئلة المهمة للإبلاغ إلى FINTRAC:

  • تغطية التقارير. هل يغطي التقارير التي تقدّمها: تقارير STR وLCTR وEFTR وLVCTR، وتقارير مدفوعات الكازينو بالنسبة إلى الكازينوهات؟ أما تقارير ممتلكات الأشخاص أو الكيانات المدرجة فتُقدَّم ورقياً.
  • قاعدة الـ 24 ساعة. هل يطبّق القاعدة على كل نوع من أنواع التقارير، ويعرض المعاملات التي جمعها حتى يتمكن فريقك من التأكد منها؟
  • التحقق من الصحة. هل يفحص الحقول الإلزامية والحقول الإلزامية إن انطبقت قبل التقديم، ويفصل التحذيرات عن الأخطاء المانعة، كما يفعل التحقق من الصحة لدى FINTRAC نفسها؟
  • مسار الاعتماد. هل يمكنك أن تُثبت من أعدّ كل تقرير وراجعه واعتمده وقدّمه، ومتى؟
  • رد FINTRAC. هل يسجّل الإقرار بالاستلام أو التحذيرات أو الرفض لكل تقرير، ويتيح لك تعديل تقرير مقدَّم أو حذفه؟ تدعم واجهة API لدى FINTRAC إجراءات الإنشاء والتعديل والحذف.
  • تحديثات المخططات. تنشر FINTRAC مخططات JSON وقواعد التحقق من الصحة لكل نوع من التقارير وتحدّثها. فمن يُبقي البرنامج متوافقاً معها؟
  • السجلات. هل يمكنك تصدير سجل لكل تقرير لأغراض مراجعة الفعالية أو الفحص الرقابي من FINTRAC؟
  • التقدير المهني. هل يبقى قرار تقديم تقرير STR بيد مسؤول الامتثال لديك؟

تصف الأقسام أعلاه كيفية تعامل منصتنا مع التحقق من الصحة والاعتماد وردود FINTRAC والسجلات.

كيف نُعدّ المنصة

  1. مكالمة تحديد النطاق. أنواع تقاريرك، ومصادر بياناتك، وكيف تقدّم التقارير حالياً.
  2. مراجعة البيانات. نتحقق من الحقول الموجودة في أنظمتك ومن بيانات الإبلاغ الناقصة.
  3. التهيئة. يضبط متخصص في الامتثال أنواع تقاريرك وحدودها وقواعد التجميع ومطابقة الحقول وأدوار المستخدمين ومسارات الاعتماد.
  4. الاختبار. نختبر باستخدام معاملات نموذجية وسابقة في بيئة اختبار معزولة (sandbox)، بمعزل عن عمليات التقديم الفعلية إلى FINTRAC.
  5. التسجيل في API. حيثما ينطبق ذلك، نساعدك في إتمام التسجيل في خدمة API لدى FINTRAC.
  6. التشغيل الفعلي. تنتقل مسارات العمل المعتمدة إلى بيئة الإنتاج.

لا يوجد جدول زمني قياسي للتنفيذ. وتُؤكَّد ضوابط الأمان وموقع الاستضافة وموقع تخزين البيانات كتابياً لكل عميل أثناء تحديد النطاق. وإذا كنت تفضّل ألا تتولى الإبلاغ بنفسك، فإن خدمة مسؤول الامتثال الخارجي لدينا تشمل الإبلاغ إلى FINTRAC.

المصادر: FINTRAC، طرق الإبلاغ إلى FINTRAC؛ تقديم التقارير عبر API لدى FINTRAC؛ استخدام نظام الإبلاغ عبر الويب لدى FINTRAC؛ الإبلاغ عن المعاملات المشبوهة؛ الإبلاغ عن المعاملات النقدية الكبيرة؛ الإبلاغ عن التحويلات الإلكترونية للأموال؛ الإبلاغ عن معاملات العملة الافتراضية الكبيرة؛ قاعدة الـ 24 ساعة. تم التحقق في 23 نوفمبر 2026. معلومات عامة، وليست استشارة قانونية.

ما برنامج الإبلاغ إلى FINTRAC؟

برنامج يساعد الجهة المُبلِّغة على إعداد التقارير التي يجب عليها إرسالها إلى FINTRAC وفحصها واعتمادها وتقديمها ومتابعتها، مثل تقارير STR وLCTR وEFTR وLVCTR. ويطبّق برنامجنا أيضاً فحوص قاعدة الـ 24 ساعة ويحتفظ بالتاريخ الكامل لكل تقرير.

ما تقارير FINTRAC التي تدعمها المنصة؟

تقارير المعاملات المشبوهة، وتقارير المعاملات النقدية الكبيرة، وتقارير التحويلات الإلكترونية للأموال، وتقارير معاملات العملة الافتراضية الكبيرة، وتقارير مدفوعات الكازينو. أما تقارير ممتلكات الأشخاص أو الكيانات المدرجة فتُقدَّم ورقياً، لذا فهي غير مشمولة.

هل تقدّم المنصة التقارير إلى FINTRAC مباشرة؟

نعم، عبر خدمة تقديم التقارير بواجهة API لدى FINTRAC (FINTRAC API report submission) بمجرد تسجيل نشاطك التجاري فيها. وحتى ذلك الحين، تُعدّ بيانات تقارير متحققاً من صحتها ومعتمدة لقناتك الحالية لدى FINTRAC.

هل يقرر البرنامج ما إذا كان يجب تقديم تقرير STR؟

لا. فهو ينظّم الإعداد والاعتماد، لكن وجود أسباب معقولة للاشتباه والسرد وقرار التقديم تبقى من مسؤولية فريق الامتثال لديك.

هل يمكننا استيراد ملفات معاملاتنا؟

نعم. الملفات المنظّمة مثل ملفات CSV المُصدَّرة هي طريقة الاستيراد الرئيسية، وتطابق المطابقاتُ القابلة لإعادة الاستخدام حقولَك مع حقول تقارير FINTRAC. وتُؤكَّد المصادر الأخرى أثناء تحديد النطاق.

هل تقديم التقارير عبر API لدى FINTRAC إلزامي؟

لا تحدد صفحات الإبلاغ لدى FINTRAC رقماً معيناً للحجم. فهي تصف نظام الإبلاغ عبر الويب بأنه موجّه لأحجام الإبلاغ المنخفضة، وتقديم التقارير عبر API بأنه موجّه للأحجام المرتفعة. وقد حصلت الشركات التي كانت ترسل أحجاماً مرتفعة عبر الأنظمة القديمة التي يجري إيقافها على فترات انتقالية للتحول إلى API، انتهت بين 6 نوفمبر 2023 و22 أغسطس 2024. ويجب على الشركة التي لديها اتصال بالإنترنت أن تُبلغ إلكترونياً، باستثناء تقارير ممتلكات الأشخاص أو الكيانات المدرجة التي تُقدَّم ورقياً، أما الشركة التي لا تملك القدرة التقنية على الإبلاغ إلكترونياً فيجب أن تستخدم النماذج الورقية.
