FINTRAC 报告软件与 API 报告提交（API report submission）

在一个平台上检查、批准和跟踪您的 FINTRAC 报告。

我们的报告平台对您的交易数据进行 24 小时规则检查、验证和审批，然后在您已完成登记的情况下通过FINTRAC API 报告提交（FINTRAC API report submission）方式提交，并保存记录。

预约咨询 继续阅读 按需报价 · 范围沟通后

FINTRAC 报告的大部分工作，在您点击提交之前就已发生。

交易数据分布在多个系统中。较小的交易可能需要根据 24 小时规则合并计算。交易执行人和受益人信息可能缺失，每份报告在提交前都需要检查，被拒绝的报告必须修正后重新提交。用电子表格和电子邮件处理这些工作，既慢又难以留存证据。

我们的平台涵盖以电子方式提交的五种报告：可疑交易报告、大额现金交易报告、电子资金转账报告、大额虚拟货币交易报告和赌场支付报告。报告什么仍由您的合规团队决定。平台负责围绕这一决定的检查、流转和记录保存。价格在范围沟通后确认。

报告如何送达 FINTRAC

有互联网连接的企业必须以电子方式向 FINTRAC 提交可疑交易报告、大额现金交易报告、大额虚拟货币交易报告、电子资金转账报告和赌场支付报告。列名人士或实体财产报告仍使用纸质表格提交。FINTRAC 的报告方式页面列出了两种电子报告系统，以及一个同时向 FINTRAC 和加拿大税务局发送 EFTR 的共享流程：

  • FINTRAC 网上报告系统（FINTRAC Web Reporting System）。您在浏览器中逐份填写并提交报告。FINTRAC 表示，该系统面向报告量较低的企业。
  • FINTRAC API 报告提交（FINTRAC API report submission）。一种系统对系统的连接，将报告数据直接发送给 FINTRAC，面向报告量较高的企业。

较旧的批量系统正在逐步停用。FINTRAC 将大量报告迁移至 API 的过渡期已经结束：LCTR 和 LVCTR 于 2023 年 11 月 6 日结束，STR 于 2024 年 7 月 3 日结束，EFTR 和赌场支付报告于 2024 年 8 月 22 日结束（FINTRAC，API 报告提交（API report submission），核查日期：2026 年 11 月 15 日）。

Three ways to file with FINTRAC

For the five electronic reports, the choice is between using one of FINTRAC's two systems directly and using a reporting platform that prepares reports and submits them through one of them. A business without the technical capability to report electronically must use FINTRAC's paper forms (FINTRAC, Methods to report).

FINTRAC API 报告提交（FINTRAC API report submission）涉及哪些内容

要使用 API，您需要一个应用程序和密钥，由您的技术管理员通过 FINTRAC 的 API 门户设置。报告量较大但尚未获得 API 访问权限的企业，可发送电子邮件至 F2R@fintrac-canafe.gc.ca 联系 FINTRAC。

FINTRAC 提供两组端点，一组用于单份报告，一组用于批量提交，每组都可以创建、更改或删除报告提交。单份报告最多可包含 500 笔交易（25 MB）。批量文件最多可包含 5,000 份报告，每份报告最多 5,000 笔交易，总大小不超过 300 MB。FINTRAC 为每种报告类型发布 JSON 架构（schema）和验证规则。

我们的平台按照 FINTRAC API 所要求的格式生成报告数据，逐份或批量提交已批准的报告，并针对每份报告记录 FINTRAC 的回复。如果您的企业尚未完成 API 登记，我们会协助您办理登记。在此之前，平台会生成经过验证和批准的报告数据，供您通过现有的 FINTRAC 渠道提交，并在报告中记录其状态。

平台涵盖的报告

以下是 FINTRAC 指引中的门槛和截止期限，即我们在FINTRAC 报告指南中所作的概述。您必须提交哪些报告，取决于您的业务和您开展的活动。

报告适用情形截止期限
可疑交易报告（STR）有合理理由怀疑交易与洗钱、恐怖主义融资或规避制裁有关。没有最低金额。在切实可行的情况下尽快
大额现金交易报告（LCTR）您收到 10,000 加元或以上的现金，无论是单笔交易，还是根据 24 小时规则须合并计算的两笔或多笔交易。15 个日历日
电子资金转账报告（EFTR）您发起或最终接收 10,000 加元或以上的国际电子资金转账，无论是单笔转账，还是根据 24 小时规则须合并计算的两笔或多笔转账。5 个工作日
大额虚拟货币交易报告（LVCTR）您收到价值 10,000 加元或以上的虚拟货币，无论是单笔交易，还是根据 24 小时规则须合并计算的两笔或多笔交易。5 个工作日

列名人士或实体财产报告以纸质方式提交，因此平台不处理此类报告。赌场支付报告适用于赌场，有其单独的工作流程。

24 小时规则检查

对于大额现金和大额虚拟货币交易，FINTRAC 的24 小时规则意味着：当您知道两笔或多笔任意金额的交易在 24 小时内合计达到 10,000 加元或以上，且由同一个人或实体进行或代表其进行，或针对同一受益人时，须将其合并报告。电子资金转账和赌场支付有各自的合并计算规则。FINTRAC 期望您在所有营业地点应用这一规则，而要在各分支机构、代理人和支付渠道之间手动做到这一点很困难。

这一规则并非对每种报告都以相同方式运作。哪些交易需要合并计算，取决于报告类型、时间、交易执行人、第三方和受益人。平台针对每种报告类型应用可配置的检查，并显示其已归组的交易。是否需要提交报告由您的团队确认。

报告提交前的验证

根据 FINTRAC 的指南，FINTRAC 网上报告系统（FINTRAC Web Reporting System）会显示两种验证消息。拒绝消息表示缺少必填信息，在补充之前报告无法提交。警告表示标记为“如适用则必填”的信息缺失或不完整。警告不会阻止提交，但如果您的记录中有该信息，您必须将其填入报告。

平台在报告进入审批之前运行检查。检查内容包括：

  • 必填字段和如适用则必填字段；
  • 格式、代码和条件字段；
  • 缺失的交易执行人或受益人信息，以及赌场支付报告中的第三方字段；
  • 重复的报告参考编号，以及交易之间缺失的关联；
  • 不一致的日期和金额。

阻断性错误与警告分开显示，以便您的团队先处理会阻止提交的问题。验证并不能保证 FINTRAC 会接受报告。

审核与批准

双人复核（maker-checker）审核可以配置。由编制人起草并验证报告，再由审核人签批。审核人可以直接在报告上添加评论并退回修改，每项操作都带有时间戳，因此您可以证明每份报告由谁在何时编制、审核、批准和提交。提醒功能会标记临近截止期限的报告。

可疑交易报告需要软件无法提供的判断。平台为叙述部分提供结构化字段，并将报告转交审批，但确立怀疑的合理理由、撰写叙述以及决定是否提交，仍由您的合规官负责。使用平台并不会转移您在报告方面的法律责任。

提交之后

已提交的报告可能附带警告返回，也可能被拒绝。平台会记录 FINTRAC 的回执和确认编号，保存已发送的 JSON 数据，将更正工作分配给团队成员，并将每个更正版本与原始版本关联，使一份报告的历史读起来是一条完整记录。您可以通过同一工作流程更改或删除已提交的报告。

已提交的报告保存在可下载为 PDF 或 CSV 的档案中。保留期限控制在范围沟通期间以书面形式确认。这为您的有效性审查人员以及 FINTRAC 的检查人员提供了带时间戳的记录，涵盖每份报告的审核和签批、已发送的 JSON 数据以及 FINTRAC 的回复。

What to look for in FINTRAC reporting software

Whichever product you consider, these are the questions that matter for FINTRAC reporting:

  • Report coverage. Does it cover the reports you file: STRs, LCTRs, EFTRs, LVCTRs and, for casinos, casino disbursement reports? Listed person or entity property reports go on paper.
  • 24-hour rule. Does it apply the rule for each report type, and show which transactions it grouped so your team can confirm?
  • Validation. Does it check mandatory and mandatory-if-applicable fields before submission, and separate warnings from blocking errors, as FINTRAC's own validation does?
  • Approval trail. Can you show who prepared, reviewed, approved and submitted each report, and when?
  • FINTRAC's response. Does it record the acknowledgement, warnings or rejection for each report, and let you change or delete a submitted report? FINTRAC's API supports create, change and delete actions.
  • Schema updates. FINTRAC publishes JSON schemas and validation rules for each report type and updates them. Who keeps the software in step?
  • Records. Can you export a record of each report for your effectiveness review or a FINTRAC examination?
  • Judgement. Does the decision to file an STR stay with your compliance officer?

The sections above describe how our platform handles validation, approval, FINTRAC responses and records.

FINTRAC 报告软件：常见问题

仍不确定？预约咨询或发送邮件至 info@amlcanada.ca。

什么是 FINTRAC 报告软件？

帮助报告实体编制、检查、批准、提交和跟踪其必须向 FINTRAC 提交的报告（例如 STR、LCTR、EFTR 和 LVCTR）的软件。我们的软件还会进行 24 小时规则检查，并保存每份报告的完整历史。

平台支持哪些 FINTRAC 报告？

可疑交易报告、大额现金交易报告、电子资金转账报告、大额虚拟货币交易报告和赌场支付报告。列名人士或实体财产报告以纸质方式提交，因此不包括在内。

它会直接向 FINTRAC 提交报告吗？

会。在您的企业完成登记后，通过FINTRAC API 报告提交（FINTRAC API report submission）方式提交。在此之前，它会生成经过验证和批准的报告数据，供您通过现有的 FINTRAC 渠道提交。

软件会决定是否提交 STR 吗？

不会。它将编制和审批流程结构化，但怀疑的合理理由、叙述以及提交决定仍由您的合规团队负责。

我们可以导入交易文件吗？

可以。CSV 导出文件等结构化文件是主要的导入方式，可重复使用的映射会将您的字段与 FINTRAC 的报告字段对应起来。其他数据来源在范围沟通期间确认。

Is FINTRAC API report submission mandatory?

FINTRAC's reporting pages don't set a volume figure. They describe the Web Reporting System as geared to lower reporting volumes and API report submission as geared to higher volumes. Businesses that sent higher volumes through the older systems being retired had transition periods to move to the API, which ended between November 6, 2023 and August 22, 2024. A business with an internet connection must report electronically, except listed person or entity property reports, which go on paper, and one without the technical capability to report electronically must use paper forms.
