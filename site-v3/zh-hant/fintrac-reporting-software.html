FINTRAC 申報軟件與 API 報告提交（API report submission）

在同一個平台檢查、批准及追蹤您的 FINTRAC 報告。

我們的申報平台對您的交易數據進行 24 小時規則檢查、驗證及審批，然後在您已完成登記的情況下透過FINTRAC API 報告提交（FINTRAC API report submission）方式提交，並保存紀錄。

預約諮詢 繼續閱讀 報價 · 範圍界定通話後

FINTRAC 申報的大部分工作，在您按下提交之前已經發生。

交易數據分散在多於一個系統。較小額的交易可能須根據 24 小時規則合併計算。交易執行人及受益人資料可能缺失，每份報告在提交前都需要檢查，而被拒絕的報告必須修正後重新提交。以試算表及電郵處理這些工作，既緩慢又難以留存證據。

我們的平台涵蓋以電子方式提交的五種報告：可疑交易報告、大額現金交易報告、電子資金轉帳報告、大額虛擬貨幣交易報告及賭場支付報告。申報什麼仍由您的合規團隊決定。平台負責圍繞這項決定的檢查、流轉及紀錄保存。收費在範圍界定通話後確認。

報告如何送達 FINTRAC

設有互聯網連線的企業必須以電子方式向 FINTRAC 提交可疑交易報告、大額現金交易報告、大額虛擬貨幣交易報告、電子資金轉帳報告及賭場支付報告。列名人士或實體財產報告仍以紙本表格提交。FINTRAC 的申報方式頁面列出兩種電子申報系統，以及一個同時向 FINTRAC 及加拿大稅務局發送 EFTR 的共用程序：

  • FINTRAC 網上申報系統（FINTRAC Web Reporting System）。您在瀏覽器中逐份填寫及提交報告。FINTRAC 表示，該系統適合申報量較低的企業。
  • FINTRAC API 報告提交（FINTRAC API report submission）。一種系統對系統的連接，將報告數據直接發送至 FINTRAC，適合申報量較高的企業。

較舊的批次系統正逐步停用。FINTRAC 讓大量申報轉用 API 的過渡期已經結束：LCTR 及 LVCTR 於 2023 年 11 月 6 日結束，STR 於 2024 年 7 月 3 日結束，EFTR 及賭場支付報告於 2024 年 8 月 22 日結束（FINTRAC，API 報告提交（API report submission），查核日期：2026 年 11 月 15 日）。

向 FINTRAC 提交報告的三種方式

就五種電子報告而言，您可選擇直接使用 FINTRAC 兩個系統之一，或使用一個準備報告並透過其中一個系統提交的申報平台。不具備以電子方式報告的技術能力的企業，必須使用 FINTRAC 的紙本表格（FINTRAC，報告方式）。

選項運作方式適用於您須設定的內容提交前的檢查
FINTRAC 網上報告系統（Web Reporting System）您在瀏覽器中逐份填寫並提交報告。據 FINTRAC 所述，適用於報告量較低的情況存取權限（須先發電郵至 F2R@fintrac-canafe.gc.ca 聯絡 FINTRAC），以及具備不同角色的用戶：資料輸入人員只能建立報告，而核實及提交人員負責提交。FINTRAC 的驗證：缺少必填資料時顯示拒絕訊息，缺少標示為「如適用則必填」的資料時顯示警告。
您自設與 FINTRAC API 的連接您的系統直接向 FINTRAC 傳送報告數據。據 FINTRAC 所述，適用於報告量較高的情況透過 FINTRAC 的 API 入口網站申請應用程式及密鑰，並按 FINTRAC 的 JSON 綱要及驗證規則自行開發，且須隨 FINTRAC 的更新而保持最新。您自行建立的任何檢查，再加上 FINTRAC 的驗證訊息。
申報平台，例如我們的平台交易數據經匯入、檢查及批准後，在您已完成登記的情況下透過FINTRAC API 報告提交（FINTRAC API report submission）方式提交。透過 FINTRAC 的 API 提交，或在您完成登記前為您現有的 FINTRAC 渠道準備報告數據報告類型、門檻、合併規則、欄位對應及審批流程，由合規專家設定。API 登記要求仍然適用。24 小時規則檢查、提交前驗證（警告與阻截性錯誤分開顯示），以及雙人覆核（maker-checker）簽批。

無論使用哪種方式，您的企業仍須對其報告負責。FINTRAC 的網上報告系統指南及API 報告提交頁面均有說明各個系統。

FINTRAC API 報告提交（FINTRAC API report submission）涉及哪些內容

如要使用 API，您需要一個應用程式及密鑰，由您的技術管理員透過 FINTRAC 的 API 入口網站設定。申報量較大但尚未取得 API 權限的企業，可電郵至 F2R@fintrac-canafe.gc.ca 聯絡 FINTRAC。

FINTRAC 提供兩組端點，一組用於單份報告，一組用於批量提交，每組均可建立、更改或刪除報告提交。單份報告最多可包含 500 宗交易（25 MB）。批量檔案最多可包含 5,000 份報告，每份報告最多 5,000 宗交易，總大小不超過 300 MB。FINTRAC 為每種報告類型公布 JSON 綱要（schema）及驗證規則。

我們的平台按照 FINTRAC API 要求的格式建立報告數據，逐份或批量提交已批准的報告，並就每份報告記錄 FINTRAC 的回覆。如您的企業尚未完成 API 登記，我們會協助您辦理登記。在此之前，平台會產生經驗證及批准的報告數據，供您透過現有的 FINTRAC 渠道提交，並在報告中記錄其狀態。

平台涵蓋的報告

以下是 FINTRAC 指引中的門檻及期限，即我們在FINTRAC 申報指南中的摘要。您必須提交哪些報告，視乎您的業務及您進行的活動。

報告適用情況期限
可疑交易報告（STR）有合理理由懷疑交易與洗錢、恐怖主義融資或規避制裁有關。沒有最低金額。在切實可行範圍內盡快
大額現金交易報告（LCTR）您收取 10,000加元或以上的現金，可以是單一交易，或 24 小時規則要求您合併計算的兩宗或以上交易。15 個曆日
電子資金轉帳報告（EFTR）您發起或最終接收 10,000加元或以上的國際電子資金轉帳，可以是單一轉帳，或 24 小時規則要求您合併計算的兩宗或以上轉帳。5 個工作天
大額虛擬貨幣交易報告（LVCTR）您收取價值 10,000加元或以上的虛擬貨幣，可以是單一交易，或 24 小時規則要求您合併計算的兩宗或以上交易。5 個工作天

列名人士或實體財產報告以紙本提交，因此平台不處理此類報告。賭場支付報告適用於賭場，設有獨立的工作流程。

24 小時規則檢查

就大額現金及大額虛擬貨幣交易而言，FINTRAC 的24 小時規則是指：當您知道兩宗或以上任何金額的交易在 24 小時內合計達 10,000加元或以上，並由同一人士或實體或代其進行，或為同一受益人進行，便須一併申報。電子資金轉帳及賭場支付各有其合併計算規則。FINTRAC 期望您在所有營業地點應用這項規則，而要在各分行、代理人及支付渠道之間以人手做到這一點並不容易。

這項規則並非對每種報告都以相同方式運作。哪些交易須合併計算，取決於報告類型、時間、交易執行人、第三方及受益人。平台就每種報告類型應用可設定的檢查，並顯示已歸組的交易。是否需要提交報告由您的團隊確認。

報告提交前的驗證

根據 FINTRAC 的指南，FINTRAC 網上申報系統（FINTRAC Web Reporting System）會顯示兩種驗證訊息。拒絕訊息表示缺少必填資料，在補上之前報告無法提交。警告表示標示為「如適用則必填」的資料缺失或不完整。警告不會阻止提交，但如您的紀錄中有該資料，您必須將其填入報告。

平台在報告進入審批前執行檢查。檢查內容包括：

  • 必填欄位及如適用則必填欄位；
  • 格式、代碼及條件欄位；
  • 缺失的交易執行人或受益人資料，以及賭場支付報告中的第三方欄位；
  • 重複的報告參考編號，以及交易之間缺失的關聯；
  • 不一致的日期及金額。

阻斷性錯誤與警告分開顯示，讓您的團隊先處理會阻止提交的問題。驗證並不能保證 FINTRAC 會接受報告。

審閱及批准

雙人覆核（maker-checker）審閱可按需設定。由編製人草擬及驗證報告，再由審閱人簽批。審閱人可直接在報告上加入評論並退回修正，每項操作都附有時間戳記，因此您可以證明每份報告由誰在何時編製、審閱、批准及提交。提醒功能會標示臨近期限的報告。

可疑交易報告需要軟件無法提供的判斷。平台為敘述部分提供結構化欄位，並將報告轉交審批，但確立懷疑的合理理由、撰寫敘述及決定是否提交，仍由您的合規主管負責。使用平台並不會轉移您在申報方面的法律責任。

提交之後

已提交的報告可能附帶警告退回，也可能被拒絕。平台會記錄 FINTRAC 的回執及確認編號，保存已發送的 JSON 數據，將更正工作分派給團隊成員，並將每個更正版本與原本版本連結，使一份報告的歷史成為一條完整紀錄。您可以透過同一工作流程更改或刪除已提交的報告。

已提交的報告保存在可下載為 PDF 或 CSV 的檔案庫中。保存期限控制在範圍界定期間以書面確認。這為您的有效性審查人員及 FINTRAC 的審查人員提供附時間戳記的紀錄，涵蓋每份報告的審閱及簽批、已發送的 JSON 數據及 FINTRAC 的回覆。

選擇 FINTRAC 申報軟件時應留意甚麼

無論您考慮哪種產品，以下是與 FINTRAC 報告相關的關鍵問題：

  • 報告涵蓋範圍。它是否涵蓋您提交的報告：STR、LCTR、EFTR、LVCTR，以及賭場適用的賭場支付報告？列名人士或實體財產報告以紙本方式提交。
  • 24 小時規則。它是否就每種報告類型應用該規則，並顯示其合併了哪些交易，以便您的團隊確認？
  • 驗證。它是否如 FINTRAC 本身的驗證一樣，在提交前檢查必填及「如適用則必填」欄位，並將警告與阻截性錯誤分開？
  • 審批紀錄。您能否顯示每份報告由誰在何時準備、審閱、批准及提交？
  • FINTRAC 的回覆。它是否記錄每份報告的確認、警告或拒絕，並讓您更改或刪除已提交的報告？FINTRAC 的 API 支援建立、更改及刪除操作。
  • 綱要更新。FINTRAC 會就每種報告類型發布並更新 JSON 綱要及驗證規則。由誰負責令軟件保持同步？
  • 紀錄。您能否匯出每份報告的紀錄，供有效性審查或 FINTRAC 合規檢查使用？
  • 專業判斷。是否提交 STR 的決定是否仍由您的合規主管作出？

以上各節介紹我們的平台如何處理驗證、審批、FINTRAC 回覆及紀錄。

我們如何設定

  1. 範圍界定通話。您的報告類型、數據來源，以及您目前如何提交報告。
  2. 數據審閱。我們檢查您的系統保存了哪些欄位，以及哪些申報數據缺失。
  3. 設定。由合規專家設定您的報告類型、門檻、合併計算規則、欄位對應、用戶角色及審批路徑。
  4. 測試。我們在沙盒環境中以樣本交易及過往交易進行測試，與實際的 FINTRAC 提交分隔。
  5. API 登記。如適用，我們協助您完成 FINTRAC API 登記。
  6. 正式上線。已批准的工作流程轉入正式環境。

並沒有標準的實施時間表。安全控制、託管地點及數據駐留會在範圍界定期間就每位客戶以書面確認。如您不想自行處理申報工作，我們的外包合規主管服務包括 FINTRAC 申報。

FINTRAC 申報軟件：常見問題

仍不確定？預約諮詢或電郵至 info@amlcanada.ca。

什麼是 FINTRAC 申報軟件？

協助申報實體編製、檢查、批准、提交及追蹤其必須向 FINTRAC 提交的報告（例如 STR、LCTR、EFTR 及 LVCTR）的軟件。我們的軟件亦會進行 24 小時規則檢查，並保存每份報告的完整歷史。

平台支援哪些 FINTRAC 報告？

可疑交易報告、大額現金交易報告、電子資金轉帳報告、大額虛擬貨幣交易報告及賭場支付報告。列名人士或實體財產報告以紙本提交，因此不包括在內。

平台會直接向 FINTRAC 提交報告嗎？

會。在您的企業完成登記後，透過FINTRAC API 報告提交（FINTRAC API report submission）方式提交。在此之前，平台會產生經驗證及批准的報告數據，供您透過現有的 FINTRAC 渠道提交。

軟件會決定是否提交 STR 嗎？

不會。軟件將編製及審批流程結構化，但懷疑的合理理由、敘述及提交決定仍由您的合規團隊負責。

我們可以匯入交易檔案嗎？

可以。CSV 匯出檔案等結構化檔案是主要的匯入方式，可重複使用的對應設定會將您的欄位對應至 FINTRAC 的報告欄位。其他數據來源在範圍界定期間確認。

FINTRAC API 報告提交是強制性的嗎？

FINTRAC 的報告頁面並無訂明報告量的具體數字。這些頁面將網上報告系統描述為適用於報告量較低的情況，將 API 報告提交描述為適用於報告量較高的情況。透過即將停用的舊系統提交較高報告量的企業曾獲過渡期遷移至 API，過渡期已於 2023 年 11 月 6 日至 2024 年 8 月 22 日期間結束。具備互聯網連接的企業必須以電子方式報告（列名人士或實體財產報告除外，須以紙本提交），而不具備以電子方式報告的技術能力的企業必須使用紙本表格。

費用是多少？

收費在範圍界定通話後確認。

我們的數據託管在哪裡？

託管地點、數據駐留及安全控制會在範圍界定期間就每位客戶以書面確認。
